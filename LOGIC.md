# Логика работы устройства и Modbus‑регистры

Нумерация регистров начинается с 0 для каждого списка отдельно (RW и RO читаются раздельно).

## Последовательность работы (после подачи питания)
1. Инициализация конфигурации (загрузка из NVS, установка значений по умолчанию при необходимости).
2. Инициализация периферии.
3. Инициализация Modbus RTU.
4. Запуск основной задачи управления (период ~250 мс).

## Логика `config_mode` (битовая маска)
`config_mode` теперь хранит состояние трёх переключателей из Settings:

- Бит 0 (`1`) — ручной режим (`manual power`).
- Бит 1 (`2`) — автозапуск по температуре.
- Бит 2 (`4`) — автозапуск по влажности.

Допустимый диапазон: `0..7` (лишние биты отбрасываются).

## Сценарии работы
### Сценарий 1: включен только ручной режим
- Вентилятор работает на `config_fan_manual_percent`.
- Если дверь открыта, скорость временно увеличивается в 2 раза относительно установленной ручной скорости, но не выше 100%; после закрытия двери скорость возвращается к установленному ручному уровню.
- Аварии температуры и влажности формируются при превышении уставки на 10 (`desired + 10`).
- Эти аварии индицируются, но скорость в ручном режиме остаётся ручной (кроме приоритетных защит: дым/авария вентилятора).

### Сценарий 2: включен только один автозапуск (температура ИЛИ влажность)
- Вентилятор стартует при превышении `desired` соответствующего канала.
- Минимальная скорость берётся из `config_fan_manual_percent`.
- Рост скорости линейный от минимума до 100% в диапазоне превышения `0..10`.
- Авария по каналу активируется при `current >= desired + 10`.

### Сценарий 3: включены оба автозапуска
- Пуск происходит по первому каналу, который превысил свой `desired`.
- Текущая скорость — максимум из двух рассчитанных каналов (по наибольшему превышению).
- Порог аварии для каждого канала отдельно: `desired + 10`.

### Сценарий 4: включены все переключатели
- Приоритет ручного режима: поведение как в Сценарии 1.

## Общие правила (для всех сценариев)
- При `config_smoke_enable = 1` и срабатывании дыма:
   - `alarm_smoke = 1`,
   - авария защёлкивается и снимается через `config_alarm_clr` только после исчезновения сигнала/устранения причины,
   - в режиме "только температура" (`manual=0`, `auto_temp=1`, `auto_humidity=0`) скорость принудительно 0%, если в Settings включена дымовая блокировка этого режима; если она выключена, авария по дыму остаётся, но скорость принудительно 100%,
   - во всех остальных режимах скорость принудительно 100%.
- При защёлкнутой `alarm_temp` или `alarm_humidity` скорость принудительно 100% до сброса ошибки; после успешного сброса поведение возвращается к обычному режиму.
- При аварии вентилятора:
   - `alarm_fan = 1`,
   - скорость принудительно 0%.
- `alarm_filter` выставляется при достижении лимита фильтра и не меняет скорость напрямую.
- Аварии лочатся и снимаются через `config_alarm_clr` по текущей реализованной политике.
- BUZZER включается при любой активной аварии (любой `alarm_* = 1`) и выключается после сброса.
- Авария вентилятора формируется по входу состояния симистора (GPIO47):
   - если `fan_percent > 0`, а напряжения на выходе нет — авария,
   - если `fan_percent == 0`, а напряжение есть — авария,
   - антидребезг: 1 секунда на установку и 1 секунда на снятие.

## Полярности входов
- Дверной концевик инверсный: 1 = закрыто, 0 = открыто.
- Датчик дыма не инверсный: 0 = нет тревоги, 1 = тревога.
- Датчик состояния симистора инверсный на уровне GPIO47: физический уровень `0` означает, что напряжение на выходе есть, физический уровень `1` означает, что напряжения нет.

## Пины (по схеме)
- Zero‑Cross: GPIO48
- TRIAC управление: GPIO6
- TRIAC state (оптопара): GPIO47
- Дверь: GPIO26
- Дым: GPIO45
- BUZZER: GPIO4
- I2C0 (дисплей/тач/RTC/EEPROM): SDA=GPIO7, SCL=GPIO8
- I2C1 (датчики, SHT31): SDA=GPIO3, SCL=GPIO2
- Modbus: DIR=GPIO20, TX=GPIO22, RX=GPIO21

## RW (holding, read/write)
0. **config_mode** — битовая маска: bit0=manual, bit1=auto_temp, bit2=auto_humidity.
1. **config_temp_desired** — желаемая температура (°C).
2. **config_humidity_desired** — желаемая влажность (%RH).
3. **config_fan_manual_percent** — уставка скорости из UI/Modbus (0–100%):
   - ручной режим: целевая скорость,
   - авто-режим: минимальная скорость старта и база линейного роста.
4. **config_filter_limit_hours** — предел фильтра (часы), 0 = отключено.
5. **config_modbus_addr** — адрес Modbus (1–247), применяется после перезагрузки.
6. **config_modbus_baud** — индекс скорости (0..3), применяется после перезагрузки.
7. **cmd_clear_filter_hours** — команда сброса ресурса фильтра (записать 1; автоочистка).
8. **cmd_clear_alarms** — команда сброса аварий (записать 1; автоочистка).

## RO (holding, read‑only)
0. **alarm_temp** — авария по температуре.
1. **alarm_humidity** — авария по влажности.
2. **alarm_smoke** — авария по дыму.
3. **alarm_fan** — авария вентилятора.
4. **alarm_filter** — предел фильтра достигнут.
5. **current_temp** — текущая температура.
6. **current_humidity** — текущая влажность.
7. **door_state** — состояние двери.
8. **smoke_state** — состояние датчика дыма.
9. **vent_active** — вентилятор активен (0/1).
10. **fan_percent** — рассчитанная целевая скорость вентилятора (%).
11. **filter_clogging_percent** — заполнение ресурса фильтра (%).
12. **service_hours** — наработка фильтра (часы, целые).
