# Подробное описание алгоритмов и последовательности работы

Документ предназначен для офлайн‑использования и описывает, как программа запускается и принимает решения, а также где это реализовано в коде.

## 1) Общая последовательность после подачи питания
1. Загрузка конфигурации из NVS и валидация значений. Если данных нет — используются значения по умолчанию. Реализация: [components/System_Config/System_Config.c](components/System_Config/System_Config.c).
2. Инициализация периферии:
   - GPIO вентилятора, нулевой переход, вход двери и вход дыма. Реализация: [components/Peripherials/Peripherials.c](components/Peripherials/Peripherials.c).
   - Фазовое управление триаком (таймеры, обработка нулевого перехода). Реализация: [components/Peripherials/Peripherials.c](components/Peripherials/Peripherials.c).
   - Шина I2C и датчик SHT31, запуск задачи опроса. Реализация: [components/SHT31/SHT31.c](components/SHT31/SHT31.c).
   - Дисплей и сенсор касания (если обнаружены). Реализация: [components/Display](components/Display).
3. Инициализация Modbus RTU (адрес и скорость берутся из конфигурации). Реализация: [components/Modbus_RTU/Modbus_RTU.c](components/Modbus_RTU/Modbus_RTU.c).
4. Запуск основной задачи Modbus, которая одновременно выполняет:
   - синхронизацию RW регистров,
   - чтение датчиков,
   - вычисление логики,
   - обновление RO регистров,
   - управление вентилятором.
   Реализация: [components/Modbus_RTU/Modbus_RTU.c](components/Modbus_RTU/Modbus_RTU.c).

## 2) Источники данных и их обновление
### 2.1 Конфигурация (RW регистры)
- Конфигурация хранится в NVS и отражается в Modbus RW регистры.
- При изменении RW регистров они валидируются и сохраняются в NVS.
- Реализация чтения/записи: [components/System_Config/System_Config.c](components/System_Config/System_Config.c), [components/Modbus_RTU/Modbus_RTU.c](components/Modbus_RTU/Modbus_RTU.c).

### 2.2 Датчик температуры/влажности (SHT31)
- Период опроса ≈ 500 мс.
- Значения фильтруются простым сглаживанием.
- Если чтение не удалось — выставляется признак недоступности.
- Реализация: [components/SHT31/SHT31.c](components/SHT31/SHT31.c).

### 2.3 Дверной концевик
- Инверсная логика: 1 = дверь закрыта, 0 = дверь открыта.
- Применяется антидребезг (время подтверждения открытия/закрытия).
- Реализация: [components/Peripherials/Peripherials.c](components/Peripherials/Peripherials.c).

### 2.4 Датчик дыма
- Прямая логика: 0 = нет тревоги, 1 = тревога.
- Реализация: [components/Peripherials/Peripherials.c](components/Peripherials/Peripherials.c).

## 3) Основной цикл управления (каждые ~250 мс)
Реализация: [components/Modbus_RTU/Modbus_RTU.c](components/Modbus_RTU/Modbus_RTU.c).

Последовательность внутри цикла:
1. Прочитать актуальный `alarm_clr` и проверить входящие RW значения.
2. Если RW регистры изменились — обновить конфигурацию и сохранить в NVS.
3. Получить снапшот конфигурации для вычислений.
4. Прочитать `current_temp` и `current_humidity` (SHT31). Если данных нет — подставить «безопасные» значения.
5. Сформировать вход `logic_input_t` (температура, влажность, дверь, дым).
6. Вызвать `Logic_step()` и получить `logic_output_t` (скорость вентилятора и аварии).
7. Обновить RO регистры Modbus (alarm/temp/hum/smoke).
8. Передать рассчитанный процент на управление вентилятором.

## 4) Логика управления скоростью
Реализация: [components/Logic/Logic.c](components/Logic/Logic.c), режимы: [components/Logic/auto_mode.c](components/Logic/auto_mode.c), [components/Logic/ventilation_mode.c](components/Logic/ventilation_mode.c), [components/Logic/exhaust_mode.c](components/Logic/exhaust_mode.c).

### 4.1 Общая функция вычисления процента
Вычисляет процент по текущему значению, уставке, порогу и аварийному порогу.

Определения:
- $e = |current - desired|$
- $E = |threshold - desired|$
- $P_{min} = config\_fan\_min\_percent$

Правила:
1. Если $current \le desired$ → скорость = $P_{min}$.
2. Если $E = 0$ и есть ошибка → скорость = 100%.
3. Если $e \ge E$ → скорость = 100%.
4. Иначе:

$$
P = P_{min} + \frac{e}{E} (100 - P_{min})
$$

Результат ограничивается диапазоном 0–100.

### 4.2 Режим Авто
1. Рассчитать процент по температуре и по влажности.
2. Выбрать максимум из двух значений.
3. При достижении `alarm` по температуре/влажности скорость форсируется в 100%.
4. Если разрешён дым и дым активен → скорость 100%.
5. При аварии вентилятора → скорость 0% и выставляется соответствующий alarm.
6. Достижение предела фильтра выставляет `alarm_filter`, но на скорость не влияет.

### 4.3 Режим Вентиляция
1. Скорость берётся из `config_fan_manual_percent`.
2. Если дверь открыта → скорость ×2 (но не более 100%).
3. При достижении `alarm` по температуре/влажности → 100%.
4. При разрешённом дыме и срабатывании датчика → 100%.
5. При аварии вентилятора → скорость 0% и выставляется соответствующий alarm.
6. Достижение предела фильтра выставляет `alarm_filter`, но на скорость не влияет.

### 4.4 Режим Вытяжка
1. Влажность игнорируется, расчёт только по температуре.
2. Авария по температуре → 100%.
3. При разрешённом дыме и активном датчике → вентилятор выключается (0%) и тревога лочится.
4. При аварии вентилятора → скорость 0% и выставляется соответствующий alarm.
5. Достижение предела фильтра выставляет `alarm_filter`, но на скорость не влияет.

## 5) Логика аварий
- Аварии по температуре, влажности и дыму лочатся.
- Сброс — через `config_alarm_clr` (Modbus RW).
- При `config_smoke_enable = 0` дым полностью игнорируется.
- Реализация: [components/Logic/Logic.c](components/Logic/Logic.c).

## 5.1) Предел фильтра
- `config_filter_limit_hours` задаёт предел в часах.
- При достижении предела выставляется `alarm_filter`, но работа вентилятора не меняется.
- Сброс достигается установкой большего лимита или уменьшением счётчика часов.

## 6) Управление вентилятором и фазовое управление
- На вход поступает процент (0–100), который используется для расчёта угла открытия триака.
- Управление синхронизировано по нулевому переходу.
- Реализация: [components/Peripherials/Peripherials.c](components/Peripherials/Peripherials.c).

## 7) Сервисные часы
- Счётчик часов увеличивается по таймеру при включённой системе.
- Доступен для чтения и записи через Modbus RW.
- Реализация: [components/System_Config/System_Config.c](components/System_Config/System_Config.c).
