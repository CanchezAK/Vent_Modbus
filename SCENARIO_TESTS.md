# Сценарии тестирования логики (на основе текущей реализации)

Ниже список корректных и некорректных сценариев. Для каждого сценария описано входное задание и ожидаемое поведение системы.

## Общие условия
- Ввод уставок по температуре и влажности — в целых значениях (°C и %RH).
- Скорость растёт пропорционально ошибке относительно диапазона `desired..threshold` и всегда со смещением `config_fan_min_percent`.
- `config_system_enable = 0` выключает систему целиком.
- `config_smoke_enable = 0` отключает использование датчика дыма.
- Дверной концевик инверсный: 1 = закрыто, 0 = открыто.
- Датчик дыма не инверсный: 0 = нет тревоги, 1 = тревога.
- При достижении лимита фильтра — alarm_filter = 1, на скорость не влияет.

## Сценарии — корректные

### S01 — Авто: ниже уставки
**Задание:**
- Режим: Авто
- `config_temp_desired=25`, `config_temp_threshold=30`, `config_temp_alarm=40`
- `config_humidity_desired=40`, `config_humidity_threshold=50`, `config_humidity_alarm=70`
- `config_fan_min_percent=20`
- Текущая температура = 24°C, влажность = 38%

**Ожидаемое поведение:**
- Температура и влажность ≤ desired ⇒ скорость = 20%.
- Аварий нет.

### S02 — Авто: малая ошибка
**Задание:**
- Режим: Авто
- Температура desired=25, threshold=30, alarm=40
- min_percent=20
- Текущая температура = 26°C (ошибка 1°C)

**Ожидаемое поведение:**
- Ошибка 1°C из 5°C до threshold ⇒ 20% + 20% × (100% − 20%) ≈ 36%.

### S03 — Авто: рост в диапазоне регулирования
**Задание:**
- Режим: Авто
- desired=25, threshold=30, alarm=40
- min_percent=20
- Текущая температура = 28°C (ошибка 3°C)

**Ожидаемое поведение:**
- Ошибка 3°C из 5°C до threshold ⇒ 20% + 60% × (100% − 20%) ≈ 68%.

### S04 — Авто: превышение threshold
**Задание:**
- Режим: Авто
- desired=25, threshold=30, alarm=40
- Текущая температура = 31°C

**Ожидаемое поведение:**
- Ошибка ≥ threshold ⇒ скорость = 100%.

### S05 — Авто: дым
**Задание:**
- Режим: Авто
- `config_smoke_enable=1`, датчик дыма = 1

**Ожидаемое поведение:**
- Авария по дыму лочится.
- Скорость = 100%.

### S06 — Вентиляция: ручная скорость
**Задание:**
- Режим: Вентиляция
- `config_fan_manual_percent=35`
- Дверь закрыта

**Ожидаемое поведение:**
- Скорость = 35%.

### S07 — Вентиляция: дверь открыта
**Задание:**
- Режим: Вентиляция
- `config_fan_manual_percent=60`
- Дверь открыта

**Ожидаемое поведение:**
- Скорость = 100% (удвоение, но не выше 100%).
- После закрытия скорость возвращается к 60%.

### S08 — Вентиляция: авария по температуре
**Задание:**
- Режим: Вентиляция
- Температура ≥ alarm

**Ожидаемое поведение:**
- Авария по температуре лочится.
- Скорость = 100%.

### S09 — Вытяжка: работа только по температуре
**Задание:**
- Режим: Вытяжка
- Температура выше desired, влажность любая
### S09a — Авто: конфликт температуры и влажности
**Задание:**
- Режим: Авто
- Температура близко к threshold, влажность далеко от threshold
- Например: temp desired=25, threshold=30, alarm=40; temp = 29°C
- hum desired=40, threshold=50, alarm=70; hum = 45%

**Ожидаемое поведение:**
- В авто выбирается больший из двух рассчитанных процентов.
- В данном примере температура ближе к threshold, значит скорость определяется температурой.

**Ожидаемое поведение:**
- Скорость определяется только температурой.
- Влажность не влияет.

### S10 — Вытяжка: дым
**Задание:**
- Режим: Вытяжка
- `config_smoke_enable=1`, дым = 1

**Ожидаемое поведение:**
- Авария по дыму лочится.
- Вентилятор выключается (0%).

### S11 — Система выключена
**Задание:**
- `config_system_enable=0`

**Ожидаемое поведение:**
- Скорость = 0%.
- Аварии не удерживаются.

### S11a — Предел фильтра достигнут
**Задание:**
- `config_filter_limit_hours=100`
- `config_service_hours=100`

**Ожидаемое поведение:**
- `alarm_filter = 1`.
- Скорость не изменяется (определяется текущим режимом).

## Сценарии — некорректные/граничные

### S12 — Некорректный режим
**Задание:**
- `config_mode=15`

**Ожидаемое поведение:**
- Санитизация режима → 0 (Авто).

### S13 — Некорректный адрес Modbus
**Задание:**
- `config_modbus_addr=0`

**Ожидаемое поведение:**
- Санитизация → 1.

### S14 — Некорректная скорость Modbus
**Задание:**
- `config_modbus_baud=9`

**Ожидаемое поведение:**
- Санитизация → 3 (115200).

### S15 — Ошибка при desired > threshold
**Задание:**
- `config_temp_desired=3000`, `config_temp_threshold=2500`

**Ожидаемое поведение:**
- В конфигурации threshold автоматически приводится к desired.

### S16 — Ошибка при threshold > alarm
**Задание:**
- `config_temp_threshold=3500`, `config_temp_alarm=3400`

**Ожидаемое поведение:**
- В конфигурации alarm автоматически приводится к threshold.

### S17 — Дым отключён
**Задание:**
- `config_smoke_enable=0`, дым = 1

**Ожидаемое поведение:**
- Дым игнорируется, авария не выставляется.

### S18 — Нулевой минимум
**Задание:**
- `config_fan_min_percent=0`
- Температура ≤ desired

**Ожидаемое поведение:**
- Вентилятор может быть остановлен (0%).

## Рискованные/аномальные сценарии (возможная некорректная работа)

### R01 — Нет данных от SHT31
**Задание:**
- Датчик температуры/влажности недоступен

**Возможный эффект:**
- Подставляются значения 255°C/100% → постоянные алармы и 100% скорости в Авто/Вентиляции.

### R02 — Полярность датчика дыма перепутана
**Задание:**
- Датчик дыма выдаёт «1» в норме и «0» при тревоге

**Возможный эффект:**
- Постоянное отключение вентилятора в режиме Вытяжка или постоянные 100% в других режимах.

### R03 — Ошибка настройки порогов
**Задание:**
- `config_temp_alarm = config_temp_desired` (или аналогично по влажности)

**Возможный эффект:**
- При малейшем отклонении сразу 100% и фиксация аварии.

### R04 — Слишком высокий минимум скорости
**Задание:**
- `config_fan_min_percent = 90`

**Возможный эффект:**
- Регулирование почти не работает: скорость всегда около максимума.

### R05 — Дребезг входа дыма
**Задание:**
- Быстрые ложные переключения входа дыма

**Возможный эффект:**
- Частые переключения режимов, нестабильная работа.

### R06 — Некорректный индекс скорости Modbus
**Задание:**
- В NVS сохранён неверный `config_modbus_baud`

**Возможный эффект:**
- Потеря связи Modbus до коррекции и перезапуска.

### R07 — Скачок/переполнение часов
**Задание:**
- Сбой таймера приводит к скачку `service_hours`

**Возможный эффект:**
- Ложное срабатывание `alarm_filter`.

### R08 — Потеря нулевого перехода
**Задание:**
- Пропуски прерываний zero‑cross

**Возможный эффект:**
- Нестабильная скорость вентилятора.

## Состояние соответствия ТЗ (кратко)
**Соответствует частично.** Реализована логика режимов, Modbus‑регистры, датчики двери/дыма, сервисные часы и алгоритмы управления вентилятором. Не реализован GUI/сенсорное управление, логотип/индикаторы, датчик аварии вентилятора (пока заглушка), а также список скоростей Modbus по ТЗ (нужны 9600/19200/38400/57600/115200). Адрес Modbus приведён к 1–247, как в ТЗ.
