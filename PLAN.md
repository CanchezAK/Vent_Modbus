# План работ (draft)

## Что предстоит реализовать
1) Логика двери:
- Вход GPIO для датчика двери.
- При открытии: умножение текущей скорости/мощности на 2 (с потолком 100%).
- После закрытия: возвращение к базовой скорости с настраиваемой задержкой (уставка).
- Индикация состояния двери (GUI/Modbus).

2) Счётчик наработки фильтра:
- Счётчик времени в часах (идёт всегда, по RTC).
- Уставка предела (в часах).
- Сброс счётчика.
- Индикация достижения предела (флаг/GUI/Modbus).

3) Адрес/скорость Modbus через регистры:
- RW-регистры для адреса (1–247) и скорости (9600/19200/38400/57600/115200).
- Сохранение в NVS.
- Применение после перезагрузки (чтение из NVS при init).
- Базовые значения — текущие CONFIG_MB_*.

4) Датчик дыма (GPIO):
- Вход GPIO с логикой: 1 = OK, 0 = ALARM.
- При ALARM: включить аварийный режим/вентиляторы на максимум (по требованиям), выставить флаг тревоги.
- Функция отключаемая (уставка).

5) Датчик аварии вентилятора:
- Источник — датчик 0 в сети (детали не определены).
- Определить, как сопоставлять 1 датчик и 2 двигателя.
- Добавить регистры/логику после уточнения.

6) Сценарии работы (предложение):
- Режим "Вентиляция": скорость = уставка пользователя (с учётом двери/дыма/алармов).
- Режим "Вытяжка": запуск только при превышении уставки температуры/влажности; иначе скорость 0.
- В обоих режимах: дверь увеличивает скорость, дым/alarms принудительно 100%. Если текущая скорость 0% — установить скорость 50% на время открытия двери, после закрытия вернуть скорость к 0 после выдержки.
